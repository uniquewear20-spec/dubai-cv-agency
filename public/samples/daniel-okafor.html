01 · SystemsSelected work, 2019 – 2026

Models are the easy part.

The hard part is everything that decides whether you can trust them on a Tuesday: what they retrieve, how they are tested, and what they do when they do not know.

  1. 01

    Guideline search for clinicians

    RetrievalEvaluationPython

    Search over a hospital group's clinical guidelines. Every answer quotes the paragraph it came from, and when the guidelines are silent the system says so instead of guessing.

    What changedDoctors stopped double-checking every answer, because each one showed its source.

  2. 02

    A release gate for model updates

    EvaluationCIInfrastructure

    A test harness that runs every candidate model against hand-written cases from real support tickets, and blocks the release if any category gets worse.

    What changedRegressions are caught before release instead of being reported by customers.

  3. 03

    Speech recognition on a budget

    On-deviceYorubaHausa

    Small speech models that run on entry-level phones over patchy networks, trained with community-recorded audio and evaluated by native speakers, not just word error rates.

    What changedVoice notes became searchable for people who never type.

  4. 04

    Cost per answer

    LLM systemsCachingRouting

    A routing layer that sends easy questions to small models and hard ones to large models, with caching in between, so the bill grows slower than the traffic.

    What changedFinance could finally forecast the line item.

02 · MethodThe last three steps

Method

  1. t = 3Evaluate

    Write the test set before the model.

    A model without an evaluation is a rumour. I start every project with the cases it must get right, the cases it must refuse, and a way to run both in minutes.

  2. t = 2Fail well

    Decide where it says "I don't know".

    Every system is uncertain somewhere. The design work is choosing where, and making that answer useful: a source, a hand-off, a better question.

  3. t = 1Ship small

    The smallest model that works, then make it boring.

    Boring means monitored, versioned, cheap to run and easy to roll back. Clever comes after it is boring, if at all.
